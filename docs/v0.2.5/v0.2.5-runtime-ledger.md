### S2 Preserved Contracts

- Local tools execute through `ToolExecutionEnvironment`, which centralizes `PATH`, `NODE_PATH`, `PYTHONPATH`, cwd, timeout/cancel handling, and redaction.
- `popen()` and `run_completed()` reject unowned executables by default. Explicit external execution is limited to intentional cases such as user Chrome/Edge browser launch.

- Optional capability state, target, and Playwright browser directories ignore unowned env overrides and only add EcoreX-owned absolute paths to `sys.path`.
- Feishu and Tongxin canaries now depend on the shared execution/provider boundary instead of Codex-private or arbitrary system PATH fallbacks.

### S3 Preserved Contracts

- Release packages now carry a `runtime/runtime-manifest.json` using schema `v0.2.5-runtime-manifest-v1`.
- Manifest paths are relative only; absolute paths, user-private paths, drive paths, URLs, and traversal are rejected by checker and release validator.
- Bundled Python, Node/npm/npx, lark-cli, native bins, and Tongxin CLI evidence must match approved EcoreX-owned layouts and expected file identities.
- Python package entries enforce known module-to-distribution mapping and exact package evidence under supported site-packages roots.
- macOS `installer-bundled` evidence requires distinct mac-arm64 and mac-x64 CPython archives plus matching wheelhouse and concrete wheel archives.
- Linux service ignores mac wheelhouse/generic repository wheels; unbundled Linux Python packages are reported as `external-required`.
- Tool states are recomputed from dependency evidence; wrappers with missing deps cannot report `ready`.
- Feishu and Tongxin S3 states are canary-level readiness signals only, not hardcoded business-flow success.
- Public release manifests cannot externalize a locally validated artifact: ready local artifacts must keep `href=downloads/<fileName>`, cannot set `external`, and checksums must bind to the same local payload path.
- Windows/macOS/Linux dependency sources now align with manifest-required WebUI startup modules: `web`, `chardet`, and `numpy`.
- `web.py` uses the PyPI range `web.py>=0.76,<0.77`; the old mutable GitHub dependency is not allowed in v0.2.5 runtime/package inputs.
- Linux installed-mode checks require both `runtime/core-requirements.txt` and `runtime/runtime-manifest.json`.
- The runtime provider treats EcoreX Linux install-root venv package paths, including `lib64`, as owned state without opening system PATH.

### S4 Preserved Contracts

- Every EcoreX-native callable built-in skill facade declares a contract with `toolName`, dependencies, probe, smoke, failure prompt, and classification.
- `skill_agent_surface` remains backward-compatible with v0.2.4 fields while carrying the v0.2.5 `toolBinding` payload.
- `SkillService.query()` and `ExtensionRegistry.list_extensions()` project the same binding contract, so WebUI skill, capability, and tool views do not drift.
- Built-in skills remain default-enabled and locked, but callable status is derived from a ToolManager schema probe plus a binding contract.
- Office/PDF skills continue to use the existing `probe/status` facade actions.
- ImageGen now has a lightweight `probe/status` action that checks script and quality-runtime availability without calling any image provider; schema-driven probes no longer need a dummy `prompt`.
- Feishu/Lark and Tongxin are mapped as canaries through `feishu_cli` and `tongxin_cli`; their deep business/auth/data probes remain S5 smoke responsibility.
- Feishu/Lark and Tongxin schema-only evidence reports `partial` with `runtimeProbeRequired=true`; wrappers or external Lark skills no longer report `ready` until S5 supplies a runtime probe.
- Caller-supplied Feishu/Lark and Tongxin probe states cannot promote canary tools to `ready` unless they include explicit `runtimeProbePassed=true`.
- Capability entries expose both runtime policy status and `toolBindingStatus`; discovery-only or disabled abilities such as Feishu CLI do not become ready at the capability layer merely because a wrapper tool exists.
- Skill and extension list APIs call `ToolManager.load_tools(start_mcp=False)` and must not auto-start MCP servers while collecting read-only registry state.
- Optional ability list/status reads static or persisted Tongxin capability state and does not run Tongxin CLI schema/data health probes; explicit configure/install and S5 smoke own those checks.
- Extension registry skill source paths are emitted as redacted refs, and MCP server descriptions no longer fall back to raw command or URL values.
- S4 release gate writes a redacted evidence artifact and fails on missing contracts, missing probe/smoke/failure fields, missing tool schemas, or ready states without probe evidence.
