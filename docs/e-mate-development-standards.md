# e-Mate 开发硬标准

## 上游核心冻结

本标准自 e-Mate Enterprise 2.0.0 起适用于本次及后续开发。

除非产品负责人给出针对具体改动的明确授权，不得修改 CowAgent 上游核心的：

- 总体实现架构和运行时控制流；
- 模块划分、职责边界和依赖方向；
- Agent、任务规划、工具执行、知识、记忆、Skills、通道等核心实现；
- 核心状态机、事实源语义和持久化模型。

常规产品开发只能在既有公开边界上完成：e-Mate 品牌与 Renderer、唯一协议适配层、桌面壳、企业租户策略、管理与审计接入、发布和更新链。优先配置、组合和适配，禁止复制核心形成平行实现，也禁止为了界面方便让前端伪造 Runtime 事实。

若需求无法在上述边界内闭环，开发必须先停止，并记录：拟修改的核心位置、现有边界为何不足、最小影响范围、迁移与回滚风险。只有取得产品负责人明确许可后才能实施。沉默、推定许可或宽泛的版本目标都不构成核心修改授权。

代码审查与发布门禁必须检查本次差异是否触及上述冻结范围；未经授权的核心修改一律阻断合并和发布。

## 已批准的单次例外

2026-08-08，产品负责人明确批准 e-Mate Enterprise 2.0.0 对现有 Core
`imagegen` ToolSpec 做一次合同扩展：在保留单图入参的同时，允许一次调用携带
2–8 个有序 `tasks`。该例外只覆盖此 ToolSpec 入参及其通过既有 ToolExecution、
ImageExecutionPool、权限、恢复、Artifact 和审计链的必要接线。

本例外不允许修改通用 ToolSpec/JSON Schema 校验器、Gateway 的
`parallel_tool_calls=false` 策略、Agent 或 subagent 架构、图片 Provider/Worker
核心状态机，也不允许建立旁路 API 或第二套批处理调度器。单图行为必须向后兼容；
批次必须有界、可幂等恢复、按后端事实排序，并逐项进入原 Usage 对账权威。

后续任何扩大批次数量、改变并行策略、推广到其他工具或修改上述冻结范围的需求，
仍需新的、逐项明确授权；本次许可不得类推。

同日，产品负责人另行明确要求注入小芯身份。该授权只允许修改 Runtime 现有模型
身份指令：e-Mate 为 Agent 产品，智能体固定为“小芯”，中文默认专业严谨并称呼
用户为“同学”，能力介绍只能覆盖当前实际可用项。不得借此修改 Agent 控制流、
提示词组装架构、工具或状态机，也不得覆盖用户明确指定的语言、语气或称呼。
