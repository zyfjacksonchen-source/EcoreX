# EcoreX 服务端留存与文件管理方案

## 1. 结论

在不影响用户使用体验和系统性能的前提下，把用户日志、聊天内容、产物留存在服务器上是可行的，但不能把上传写入放进对话主链路。

建议采用“本地优先 + 异步同步 + 服务端分层存储”的方案：

- 用户请求、模型回复、产物生成仍先落到本地现有 SQLite/文件体系，保证当前体验不变。
- 同步任务写入本地 outbox 队列，由后台 worker 在空闲或响应结束后批量上传。
- 服务端先接收元数据和小文本，大文件产物延迟、分片、限速上传。
- 服务端不可用、网络慢、上传失败时，只影响同步状态，不影响用户继续使用。

## 2. 文件管理与命名规范

### 2.1 文档和代码文件

后续 EcoreX 相关计划文档统一放在：

```text
docs/ecorex/
```

命名规则：

- 使用小写英文、短横线分隔。
- 文件名表达业务主题和执行目的。
- 不把服务器地址、账号、密钥、企业名称等敏感信息写入文件名。

已建立和建议使用的文件：

```text
docs/ecorex/wecom-web-login-execution-plan.md
docs/ecorex/mvdcm-admin-clone-plan.md
docs/ecorex/server-side-storage-plan.md
```

### 2.2 服务端用户数据目录

建议新环境服务端统一使用独立数据根目录，和现有生产后台隔离：

```text
/srv/ecorex-agent-admin/userdata/
```

推荐目录结构：

```text
/srv/ecorex-agent-admin/userdata/
  org/{org_id}/
    user/{user_key}/
      sessions/{yyyy}/{mm}/{session_id}/
        session.json
        messages-{seq_start}-{seq_end}.jsonl.gz
        artifacts/
          {request_id}/
            {artifact_id}-{safe_name}
        logs/
          {yyyy}-{mm}-{dd}.jsonl.gz
      uploads/{yyyy}/{mm}/{dd}/
        {upload_id}-{safe_name}
```

命名规则：

- `org_id`：企业或租户 ID；单企业版本可先固定为 `default`。
- `user_key`：用户标识的稳定哈希，避免直接暴露邮箱、手机号、姓名。
- `session_id`：沿用当前会话 ID。
- `request_id`：一次用户请求或模型运行的 ID。
- `artifact_id`：产物 ID，服务端生成或沿用客户端生成 ID。
- `safe_name`：原始文件名清洗后的展示名，只保留字母、数字、短横线、下划线、点号；原始文件名放在元数据里。
- 大小写统一小写；不把 token、密码、邮箱、手机号放入路径。

### 2.3 数据类型分层

建议把数据分为四类，分别控制同步策略：

| 类型 | 示例 | 同步策略 |
| --- | --- | --- |
| 事件日志 | 登录、报错、模型调用状态 | 已有基础上增强，批量 JSONL 上传 |
| 聊天文本 | 用户消息、助手回复、工具摘要 | 默认可同步，按会话批量上传 |
| 产物元数据 | 文件名、类型、大小、hash、创建时间 | 默认同步 |
| 产物文件 | 图片、文档、音频、压缩包、生成文件 | 默认延迟同步，可按大小和策略开关控制 |

## 3. 推荐技术方案

### 3.1 客户端/网页端本地优先

当前项目已经具备本地留存基础：

- `agent/memory/conversation_store.py` 保存会话和消息。
- `agent/protocol/run_ledger.py` 记录运行生命周期。
- `channel/web/web_channel.py` 已把工具产物挂到消息 extras 中。
- `deploy/ecorex-admin-api/ecorex_admin_api.py` 已有 `/client/events` 接收 usage/error 事件。

后续不要替换这些链路，而是在成功本地落盘后追加同步任务：

```text
用户发送消息
  -> 本地保存消息
  -> 正常生成回复
  -> 本地保存回复和产物元数据
  -> 写入 sync_outbox
  -> 后台 worker 异步上传
```

### 3.2 本地 outbox 队列

在本地 SQLite 增加同步队列表：

```text
sync_outbox
  id
  event_type
  payload_json
  blob_path
  content_sha256
  status
  attempts
  next_retry_at
  created_at
  updated_at
```

处理规则：

- 写队列必须轻量，不做网络请求。
- 后台 worker 每次批量取 20-100 条。
- 失败指数退避，最多重试后保留待人工诊断。
- 服务端 5xx、超时或限流时自动熔断一段时间。
- outbox 超过容量阈值时优先保留聊天文本和元数据，大文件延后。

### 3.3 服务端接口

建议在 Admin API 增加独立同步接口，不复用登录接口：

```text
POST /client/sync/events
POST /client/sync/messages
POST /client/sync/artifacts
PUT  /client/sync/artifact-blobs/{artifact_id}
GET  /client/sync/status
```

接口要求：

- 继续使用现有客户端授权机制，校验用户 token 和 client key。
- 所有请求支持幂等键，避免重复上传造成重复消息。
- 大文件产物走分片或预签名上传；第一阶段可以先支持小文件直传。
- 服务端只返回同步确认，不参与用户对话生成。

### 3.4 服务端存储

建议分两层：

- 关系型数据库：保存用户、会话、消息索引、产物索引、同步状态。
- 文件系统或对象存储：保存 JSONL 压缩包和产物二进制。

第一阶段如果只部署在单台服务器，可以先使用服务器本地目录；后续数据量变大时迁移到对象存储。

## 4. 不影响体验和性能的关键措施

### 4.1 主链路不等待上传

用户发送消息和接收回复的主链路只做本地写入，不等待服务端同步成功。同步状态可以在后台、管理端或诊断页查看，但不阻塞聊天。

### 4.2 批量、压缩、去重

- 聊天消息按会话批量上传，使用 JSONL + gzip。
- 产物文件计算 `sha256`，服务端已有相同内容时只保存引用。
- 同一消息多次更新 extras 时合并后上传，避免重复同步。

### 4.3 大文件延迟和限速

产物文件建议设置默认策略：

- 小于 10 MB：后台自动上传。
- 10-100 MB：仅在空闲、网络良好时上传。
- 大于 100 MB：默认只同步元数据，除非企业策略开启。

上传 worker 要限制并发和带宽，避免影响模型调用、下载页面、后台 API。

### 4.4 降级策略

当服务器不可用或上传失败：

- 用户继续正常使用。
- 本地队列保留未同步数据。
- 后台按退避策略重试。
- 管理端显示“最近同步时间”和“未同步条数”。

## 5. 安全、隐私与合规

这部分必须在开发前锁定默认策略，因为聊天内容和用户产物可能包含敏感信息。

建议默认：

- 传输全程 HTTPS。
- 服务端磁盘加密或对象存储加密。
- 上传前做敏感信息基础脱敏：token、api key、password、secret、手机号、邮箱可按策略遮罩。
- 管理后台按角色控制查看权限，普通管理员不能直接查看完整聊天内容。
- 支持企业级开关：不同企业可选择“只同步日志”“同步聊天”“同步产物文件”。
- 支持保留周期：
  - 事件日志：30-90 天。
  - 聊天内容：默认 180 天或按企业配置。
  - 产物文件：默认短周期，或只保留元数据。
- 支持用户数据导出和删除。

## 6. 分阶段实施

### Phase 1：只同步日志和索引

- 扩展现有 `/client/events` 或新增 `/client/sync/events`。
- 上传 usage/error、运行状态、会话索引、产物元数据。
- 不上传完整聊天正文和产物文件。

验收标准：

- 不影响现有登录、聊天、下载、后台管理。
- 服务端能看到用户活跃、错误、会话数量、产物数量。
- 断网或服务端异常时客户端无明显卡顿。

### Phase 2：同步聊天正文

- 增加本地 outbox。
- 上传用户消息、助手消息、工具摘要和消息 extras。
- 服务端按会话展示或检索。

验收标准：

- 一次聊天结束后 5-30 秒内服务端可查看。
- 重复上传不会产生重复消息。
- 1000 条历史消息批量同步不影响前台对话。

### Phase 3：同步产物文件

- 上传小文件产物。
- 对大文件做分片、限速、去重。
- 管理端支持按用户、会话、时间查看和下载。

验收标准：

- 小文件自动同步成功。
- 大文件同步失败不会影响聊天。
- 服务端磁盘容量、上传队列、失败率可监控。

## 7. 风险与默认选择

风险：

- 聊天和产物可能包含商业敏感信息，必须先做权限和保留策略。
- 如果把上传放在主链路，会直接影响用户对话速度。
- 产物文件长期留存会快速消耗服务器磁盘。
- 管理后台查看聊天内容会带来权限和审计要求。

默认选择：

- 第一版只做单企业、当前新环境服务端。
- 默认启用日志和元数据同步。
- 聊天正文同步作为明确开关。
- 产物文件默认只同步小文件，大文件只保留元数据。
- 所有同步都是异步、可重试、可关闭。
