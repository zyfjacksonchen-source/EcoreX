# EcoreX R10 - Enterprise Capability Policy Client

Date: 2026-06-10

## Scope

This record covers the Admin-to-desktop capability policy loop.

Goal alignment:

- Administrators can configure optional capability policy centrally.
- Desktop clients can fetch that policy without exposing Admin credentials.
- First-use capability installation can use the enterprise mirror or offline cache.
- Optional capability installation can be disabled centrally.
- Agent core and CowAgent-compatible skill/MCP internals remain unchanged.

## Implemented

### Admin API

Updated:

- `deploy/ecorex-admin-api/ecorex_admin_api.py`

New client endpoint:

- `GET /client/capability-policy`
- Alias: `GET /capability-policy/client`
- Auth: `X-EcoreX-Client-Key`

Response shape:

```json
{
  "ok": true,
  "policy": {
    "mirror": "https://pypi.org/simple",
    "mode": "ask",
    "offlineCache": "...",
    "updatedAt": "..."
  },
  "capabilities": [],
  "updatedAt": "..."
}
```

### Desktop Runtime

Updated:

- `desktop/electron/capabilities.ts`
- `desktop/scripts/install-capability.py`
- `desktop/scripts/stage-runtime-win.ps1`
- `desktop/scripts/stage-runtime-mac.sh`
- `desktop/src/App.tsx`
- `desktop/src/services/ecorexApi.ts`
- `desktop/src/vite-env.d.ts`

Behavior:

- CapabilityManager fetches enterprise capability policy with the client event key.
- Policy is cached under Electron `userData` as `capability-policy.json`.
- If the Admin API is unavailable, cached policy remains usable.
- If policy mode is `disabled`, optional capability installation is blocked in the desktop app.
- If a PyPI mirror is configured, installation passes `--index-url` to pip.
- If an offline cache is configured as an HTTP URL, file URL, or absolute local path, installation passes `--find-links` to pip.
- Settings capability rows can show Admin policy status.
- Runtime staging now writes `capabilityPolicyUrl` into `enterprise-policy.json`.
