EcoreX 能实现什么

Agent + 企业内部工作台

EcoreX 把对话、项目文件、数据分析、素材创意、投放复盘、PPT/表格/图片产物、飞书协作和自动化流程收进一个桌面工作台，让员工从“到处打开工具”变成“在一个任务线上持续推进”。

能力概览

核心差异化

避免员工被 N 多 Agent 工具切成散点，EcoreX 把点聚合成线。

单个工具能完成一个动作，但企业真正需要的是连续工作流：任务目标、过程记录、文件资料、权限、产物、复盘和后续自动化都能回到同一个项目里。

散点问题

员工在多个 Agent、网页工具、聊天窗口和本地脚本之间切换，过程难追踪，结果难沉淀，权限也难统一。

线性工作流

EcoreX 以项目为单位组织任务、上下文、文件、状态树和产物，任务没结论不会被标成完成。

企业工作台

企业管理、客户资料、投放数据和内部 SOP 留在本地与企业托管范围内，再按角色开放能力。

开发价值

让亦芯拥有自己的超能力 Agent，而不是被外部工具链牵着走。

EcoreX 的价值不只是接入模型，而是沉淀一套可控、可审计、可扩展的企业 Agent 工程底座：既能适应大厂 AI 生态，又能把管理、客户数据和自动化工作流留在自己的工作台内。

统一入口

把分析、生成、执行、协作和复盘放到同一个桌面工作台，减少员工在多个工具之间复制粘贴。

企业沉淀

可控扩展

交付效率

能力概览

AI 连接生态

从 MCP 为主流，逐渐走向 CLI-first；未来会是 everything CLI。

今年开始，AI 连接生态正在从 MCP 为主流，逐渐走向 CLI-first。MCP 更适合做标准化工具发现、schema 描述和服务握手；CLI 更接近 Agent 的真实操作面。它稳定、可脚本化、可审计、可复用现有权限模型，也能把复杂企业系统拆成一条条可验证命令。飞书 CLI、企业微信 CLI、钉钉 CLI 这类入口，会把审批、消息、文档、表格、组织通讯录和会议等能力开放给 Agent。

为什么 CLI 适合 Agent

命令输入、stdout/stderr、exit code 和文件产物天然适配 Reasoning + Action 循环，Agent 可以执行、读取、纠错、重试并沉淀结果。

为什么不只靠 MCP

MCP 是协议与发现层，CLI 是业务系统的动作层。EcoreX 可以用 MCP 管理工具描述，也可以用 CLI 完成真实企业动作。

企业系统会 CLI 化

飞书、企业微信、钉钉等协作系统如果开放 CLI，Agent 就能在企业已有授权边界内操作文档、表格、审批、消息和组织数据。

EcoreX 的连接方式

管理员把 CLI 加入托管范围和白名单，EcoreX 再通过权限确认、项目隔离、日志与产物卡片，把外部能力收进内部工作台。

  1. 外部系统 CLI飞书 / 企业微信 / 钉钉 / 大厂 Agent CLI
  2. EcoreX 托管白名单、授权、路径、角色权限
  3. Agent LOOP执行、观察、纠错、重试、验证
  4. 企业工作台产物、状态、审计、记忆、自动化

技术说明

Harness 工程展开

Harness 是让 Agent 从“能跑一次”变成“可控、可恢复、可交付”的工程主体。

31.5 万行工业级 Agent 参考实现的启发是：真正难的不是一次工具调用，而是让每轮行动都被约束、被记录、可回滚、可接力、可校验。EcoreX 把这套思路落到开发中，覆盖任务状态树、权限确认、项目隔离、Skill 白名单、MCP 托管、产物持久化、真实安装版 smoke 和线上下载一致性。

上下文与记忆约束

通用对话不主动读取项目文件；项目记忆、账号配置、会话恢复点和产物索引分层管理，避免上下文污染。

行动前后校验

工具调用前检查权限、路径、Skill 白名单、MCP 连接和 CLI 授权；工具返回后必须有结论、产物或明确失败原因。

并发与接力

会话切换不应中断后台任务；用户在授权、扫码、确认之后的补充输入会接回当前 Loop，而不是变成排队噪音。

发布与安装 smoke

打包前后校验生产规则、真实安装版输入、Skill/MCP 预装、文件预览、联网搜索、模型适配和源代码/本机授权排除。

渐进式披露

用户只看到任务阶段、必要确认、结果和失败原因；底层桥接日志、参数拼接、原始 JSON 和内部重试不进入聊天主视图。

企业边界

企业数据库、本地工作台、权限、客户资料和自动化工作流留在 EcoreX 内部，由管理员治理能力开放范围。

生产规则静态校验 Agent runtime smoke Electron E2E 安装包输入与真实运行 smoke 文件预览 / 联网搜索验证 模型适配器与 vue-office 校验 打包清理、源代码排除与发布一致性检查

桌面技术壳

桌面端使用 Electron，界面使用 React，本地边界由主进程守住。

01Electron 桌面壳

负责安装包、窗口、系统文件打开、桌面快捷方式、开机启动入口和本机能力边界。

02React 渲染层

负责对话、项目、设置、技能、文件预览、状态树和富文本产物等交互体验。

03Electron 主进程

通过 IPC 管理账号角色、权限确认、文件系统、模型配置、MCP/Skill 状态与本地执行请求。

04本地执行引擎

在受控目录和受控权限下调度终端、文件、联网、文档、图像和外部 CLI 能力。

技术说明

Agent 选型

React 是界面框架；Agent 运行范式采用 ReAct，也就是 Reasoning + Action。

EcoreX 不是简单聊天框。它会先理解目标和约束，再选择工具行动，拿到结果后继续推理、校验和沉淀，直到给出可见结论或明确失败原因。

Reasoning

理解用户目标、项目记忆、当前文件、权限模式和可用工具，形成下一步计划。

Action

调用 MCP、Skill、CLI、终端、文件系统、联网检索、图像与文档能力，并把进度写回任务状态。

Reflection

校验工具输出是否满足目标。若没有结论、没有产物或没有可执行下一步，状态不能伪完成。

技术说明

运行逻辑

每个任务沿着 Observe、Reason、Plan、Act、Verify、Persist 循环推进。

  1. Observe读取用户目标、会话历史、项目资料、@ 文件、权限模式和可用能力清单。
  2. Reason / Plan拆解任务树，选择是否需要联网、MCP、Skill、CLI、终端或文档工具。
  3. Act串行或并发执行工具，把关键动作、阻塞点和中间结果持续回写到会话。
  4. Verify检查文件是否真实生成、配置是否生效、预览是否可打开、任务是否真的有结论。
  5. Persist保存会话、任务状态、项目索引、产物卡片和恢复点，切换会话后后台任务继续可追踪。

技术说明

记忆如何管理

记忆按账号、项目、会话和产物分层保存，默认不跨项目污染。

账号记忆

本机超级管理员、管理员和普通用户的配置与权限分离；不同用户登录后进入自己的后台、模型配置和能力范围。

项目记忆

客户资料、投放数据、长期 SOP、上传文件和生成产物进入项目资源树，项目对话可通过 @ 明确引用。

通用对话隔离

通用会话不主动查询项目私有文件，避免测试项目、客户资料或临时文件混入公共上下文。

技术说明

Hooks 与能力底座

Hooks 像任务生命周期的检查点，围绕工具调用前后持续治理。

Pre调用前检查

判断角色权限、项目边界、路径风险、Skill 白名单、MCP 连接状态和 CLI 授权状态。

Run执行中同步

把工具运行进度、阻塞提示、重试建议和后台任务状态同步到任务树。

Post结果后处理

解析输出、登记产物、生成预览卡片，失败时保留原因和下一步建议。

Admin能力治理

超级管理员和管理员可安装、配置、重置 Skill，并把通过审核的能力加入白名单。

技术说明

Skill 管理与渐进式披露

Skill 是企业能力包；渐进式披露让用户只看到必要进度，不暴露底层噪音。

超级管理员和管理员可以安装、启用、禁用、重置 Skill，也可以用内置 Skill Creator 创建新能力并加入白名单。普通用户只看到被授权后的业务能力与结果。

托管来源

内置 lark-cli、OfficeCLI、OpenCLI、agent-skill-creator 等能力包，默认只加载 EcoreX 托管范围。

管理员治理

能力安装、配置、白名单、重置初始状态由超级管理员和管理员控制，便于测试和上线前校验。

渐进式披露

对用户展示任务阶段、必要确认和最终结论；隐藏参数拼接、内部任务更新、冗余日志和底层桥接噪音。

结果归档

Skill 生成的表格、PPT、图片、网页或文档进入产物卡片和项目文件，可继续预览、引用和复用。

技术说明

MCP 运行逻辑

MCP 把外部工具变成可发现、可授权、可审计的 Agent 能力。

EcoreX 通过托管配置加载 MCP 服务，建立 stdio 或本地连接，读取工具清单与 schema，再由 Agent 在权限边界内选择调用。

  1. 注册从 EcoreX 托管配置加载服务，不扫描用户私人插件目录。
  2. 握手启动 MCP 进程或连接本地服务，获取工具、资源和参数 schema。
  3. 决策Agent 根据任务、项目边界和权限模式选择合适工具。
  4. 调用参数先经过清洗与路径校验，再把执行结果写入任务状态和会话。
  5. 收敛成功产生产物或结论；失败则返回明确原因、重试建议和恢复点。

技术说明

安全护栏

核心原则是最小权限、显式授权、托管白名单和项目边界。

角色权限超级管理员管理本机用户、管理员和能力配置；普通用户只使用自己被授权的后台和 Skill。
Skill 白名单默认只加载 EcoreX 托管范围内能力，不调用用户本机个人编程插件。
路径隔离项目文件、产物、中间文件和系统目录按作用域校验，避免跨项目读写。
命令治理高风险终端动作、外部 CLI 调用和文件覆盖动作进入聊天框内权限确认流程。
密钥管理API Key 和外部授权只进入受控配置，不写进网页、安装包说明或可公开产物。
污染防护任务输出必须有结论、产物或明确失败原因；日志、测试数据和临时上下文不进入其他项目记忆。
